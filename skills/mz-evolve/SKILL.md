# 蛮子品牌演化

## 适用范围

用户说「复盘这轮投放」「增加产量」「四个平台越来越难维护」时使用。没有实际发布数据时只做结构体检，标注实效验证缺失。

## 流程

1. 先按 `CLAUDE.md` 的必读清单读取开工上下文（含状态板及记忆索引），再读实际投放目录、实体表与 `specs/`；沿用已定标准，不临时放宽标准迁就旧稿。
2. 只用已获授权的原始数据；为每个平台分别记录观察窗口、指标口径与来源。未知不是零，跨平台数值不可直接相加比较。
3. 同时检查两条线：新增可复用实践与有效读者反馈；以及每次制作耗时、维护步骤、重复事实和渠道适配负担。播放量是渠道现象，不替代意向关联度。
4. 在 `docs/reviews/` 形成一份编号复盘，推荐一项保留、一项简化或停止，以及验证下一轮改动的小实验；没有证据时不编造增长归因。
5. 先提出选择标准与护栏的最小变更建议，附复盘依据；对已由人定标的 `specs/` 标准、`specs/style/` 正负例及承载这些标准的护栏脚本，逐项记录人确认后才使变更生效，不静默放宽红线。纯实现修复同样不豁免确认，且不得改变已确认判据；按 `mz-proto` 流程第 5 步的映射、用例与期望结果完成变更前后回归，将差异及结果指针记入本次复盘，不以当前稿退出 0 替代回归。没有已确认回归集或结果不符时保留旧护栏，不使变更生效。归档、删除、修改关联项目、扩大投放或付费之前请人确认；每个新作品子目录即时登记实体表。
6. 按 `mz-init` 流程第 4 步的审阅定义核对脚本后，运行项目规则检查，更新状态板和必要的里程碑。需要改方向时回到 init 由人确认，需要补依据时回到 research；常规新作品转 proto 沿用已定标准逐件制作与验收，需要改标准时转 proto 重定标。复盘通过不替代新作品的制作授权、人审或发布授权。

## 放行

信息收益与维护负担都有依据或明确缺失说明，下一轮只改变可验证的少量条件；人批准实验范围和新的发布动作。涉及已定标标准、正负例或护栏判据的变更已有逐项人确认记录，承载判据的脚本变更已通过回归；否则保留原标准，停留在变更建议。未取得增长与成本基线时，不声称已具备放量条件。
