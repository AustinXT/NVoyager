# 蛮子品牌演化

## 适用范围

用户说「复盘这轮投放」「增加产量」「四个平台越来越难维护」时使用。没有实际发布数据时只做结构体检，标注实效验证缺失。

## 流程

1. 读取开工协议、意向书、状态板、实际投放目录与实体表；沿用 `specs/` 的标准，不临时放宽标准迁就旧稿。
2. 只用已获授权的原始数据；为每个平台分别记录观察窗口、指标口径与来源。未知不是零，跨平台数值不可直接相加比较。
3. 同时检查两条线：新增可复用实践与有效读者反馈；以及每次制作耗时、维护步骤、重复事实和渠道适配负担。播放量是渠道现象，不替代意向关联度。
4. 在 `docs/reviews/` 形成一份编号复盘，推荐一项保留、一项简化或停止，以及验证下一轮改动的小实验；没有证据时不编造增长归因。
5. 改选择标准与护栏，少加目录和流程。归档、删除、修改关联项目、扩大投放或付费之前请人确认；每个新作品子目录即时登记实体表。
6. 运行项目规则检查，更新状态板和必要的里程碑。需要改方向时回到 init 由人确认，需要补依据时回到 research，需要重定标时回到 proto。

## 放行

信息收益与维护负担都有依据或明确缺失说明，下一轮只改变可验证的少量条件；人批准实验范围和新的发布动作。未取得增长与成本基线时，不声称已具备放量条件。
